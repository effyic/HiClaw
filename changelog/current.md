# Changelog (Unreleased)

Record image-affecting changes to `manager/`, `worker/`, `copaw/`, `openclaw-base/` here before the next release.

---

- fix(agent): update file-sharing path guidance for CoPaw and Team Leader agents to use `/root/hiclaw-fs/agents/...` instead of the retired `/root/.hiclaw-worker/...` path.
- feat(controller): add per-agent `spec.resources` support for Manager, Worker, Team Leader, and Team Worker CRDs.
- feat(sensitive-content): add standalone sensitive content management service (rule/type CRUD, policy snapshot distribution, hit-event collection and metrics, versioned SQL migrations in a dedicated `sensitive_content` schema; new `hiclaw-sensitive-content` image with `build-sensitive-content` / `push-sensitive-content` Makefile targets).
- feat(openagno): add `SensitiveContentGuardrail` for Agno Workers — local policy snapshot cache, normalization/text/regex detection, seven response actions (block/redact/fixed-reply/etc.), anonymous idempotent hit reporting, configurable fail-open/fail-closed.
- feat(helm): integrate sensitive-content into the chatai chart — optional Deployment/Service behind `sensitiveContent.enabled`, pre-install/pre-upgrade migration Job, Secret-backed runtime credentials (`sensitiveContent.existingSecret` supported), and `SENSITIVE_CONTENT_*` env injection into Agno Workers.
- feat(sensitive-content/openagno): link hit events to plaintext `session_id` for admin session drill-down — new `0002` migration adds `hit_event.session_id` (empty-string default for legacy rows) plus a tenant/session/time index; `HitEventIn`, hit-event insert, and internal batch API accept the field; new paginated admin detail API `GET /api/v1/tenants/{tenant_id}/hit-events` (rule_id/type_id/session_id/time-range filters, response carries `session_id` for jumping to `/effyic/v1/sessions/{session_id}`); `metrics/by-rule` now returns `last_session_id`; openagno guardrail reporter sends plaintext `session_id` alongside the existing session fingerprint (commit hash TBD — fill in on commit).
- fix(helm/sensitive-content): align the chart's default sensitive-content port with the service/image default (`8110` → `8091`); document the fresh-install ordering constraint between the pre-install sensitive-content migration Job and the post-install db-init Job (pre-create the database or enable via `helm upgrade`) in values.yaml, the Job template, and `sensitive-content/README.md`; add a cross-package contract test in `openagno/tests/` that mounts the real sensitive-content internal API against the openagno snapshot client and hit reporter.
- feat(sensitive-content/openagno): add eighth response action `ADJUST_PROMPT` — allow the request and inject type `prompt_guidance` into Agno instructions (with conflict-priority wording); migration `0003` seeds global `self_harm` type (`priority=70`) plus a Chinese baseline keyword rule set (idempotent `WHERE NOT EXISTS`, no resurrect of deleted rows, conditional `policy_version` bump); merge-then-validate on type update rejects non-ADJUST configs that carry `prompt_guidance` (commit hash TBD — fill in on commit).
- feat(sensitive-content/openagno): scope enabled sensitive-content rules to explicit Agent bindings — add `role_code`-keyed binding CRUD, per-Agent policy versions, Agent-specific snapshots/cache isolation, global-override following, automatic unbinding on rule deletion, and `role_code` hit-event filtering; existing Agents intentionally start with no bindings (commit hash TBD — fill in on commit).
- chore(sensitive-content/helm): keep chart deploy backend-only — exclude `web/` from image build context (`.dockerignore`), document that the admin UI is local-only and that the service shares ChatAI/openagno `postgres.*`.
- fix(sensitive-content/openagno): make the first async Agent request load its policy before fail-open evaluation, and align Worker action handling with the management API's canonical `reply_text` / `business_action` fields while retaining legacy field compatibility.
- fix(sensitive-content): key frontend Agent rule bindings and hit-event filtering by tenant-scoped `role_code` instead of leaking the unrelated `agno_agent.id`; resolve the internal ID only inside the service and remove the pre-release numeric-ID management routes.
- fix(helm/chatai): source the sensitive-content admin credential directly from the primary ChatAI Worker's API-token Secret, leaving the sensitive-content Secret responsible only for runtime and fingerprint credentials.
- feat(sensitive-content/openagno): bind Agents to sensitive types instead of individual rules — migration `0005` creates `agent_type_binding`, migrates distinct type IDs from legacy rule bindings (with cross-type override precheck), and drops `agent_rule_binding`; Admin API `/agents/{role_code}/sensitive-types`; snapshots filter by `binding_type_ids`; override rules must share `type_id` with the global target (`override_type_mismatch`); openagno `PolicySnapshot.binding_type_ids` aligned (commit hash TBD — fill in on commit).

- **OpenHuman runtime**: OpenHuman added as the fourth Worker runtime with native Matrix support via `channel-matrix` feature flag; includes controller routing (K8s + Docker backends), Dockerfile, entrypoint script, agent template, Helm chart integration, and Makefile build targets.
- **Multi model providers**: Worker, Team, and Manager specs can now select a Higress model provider via `spec.modelProvider`; the controller resolves the provider, injects the matching gateway URL into runtime config, and authorizes consumers only on the selected AI route.

**Bug Fixes**

- **CoPaw Worker heartbeat**: CoPaw worker templates now seed heartbeat at a 10-minute interval so Team Leader agents created from the worker template can run heartbeat turns without requiring an explicit Team CR heartbeat spec.
- **Helm CRDs**: Removed unsupported `propertyNames` schema fields from Worker and Team CRDs so Kubernetes API servers accept the chart CRDs.
- **CoPaw local runtime paths**: CoPaw direct-run defaults now honor `COPAW_INSTALL_DIR` and `COPAW_WORKING_DIR` before falling back to local home-directory paths, while container entrypoints can continue to pass explicit directories.
